Relayvora/Claude Code usage limit

GUIDE / USAGE LIMITS

Claude Code hit its usage limit. Keep working in Codex.

When Claude Code stops with “You’ve hit your session limit · resets …”, you can wait for the reset or carry on in another agent. Relayvora makes the second option take one command instead of a twenty-minute recap.

npm install -g relayvoraFree · open source · local-first

What happens when Claude Code hits its limit

The session stops mid-task. Your changes are on disk, but the context is not: what you asked for, what the agent already tried, which test is still failing. Opening Codex means explaining all of it again, or pasting a transcript that can run to hundreds of thousands of tokens.

Hand the task to Codex in one command

Run this in the project folder:

relayvora handoff --from claude --to codex --verify auto --confirm

Relayvora reads your latest Claude Code session for the project, collects the uncommitted changes and the commits made during the session, runs the project’s own typecheck, lint and test commands, and writes a short handoff (4,000 tokens by default). After you confirm, it starts Codex in the same terminal with the handoff loaded.

Prefer OpenCode? Use --to opencode. Working in an editor panel? Add --copy and paste the handoff.

Why a verified handoff beats a summary

Agents are good at sounding sure about work that is not finished. Every line in a Relayvora handoff says where it came from:

  • [observed]: Relayvora saw it in Git or ran the command itself, with the real exit code.
  • [user]: something you stated.
  • [agent-reported] and [inferred]: claims the next agent should check before relying on them.

So Codex does not take “tests pass” on faith. It sees the failing test and its output.

Save the handoff before you hit the limit

relayvora hooks install

With hooks installed, Claude Code runs Relayvora when a turn ends because of a usage or rate limit, just before the conversation is compacted, and when the session ends. The checkpoint is waiting before you need it, and continuing is relayvora launch <id> --to codex.

Codex limits work the same way

Relayvora also reads Codex’s limit errors and its 5-hour and weekly usage windows, and flags a session at 90% or more. Hand off in the other direction with relayvora handoff --from codex --to claude --verify auto --confirm.

When not to switch

A small session that was active a moment ago is usually cheaper to continue. Relayvora’s home screen and relayvora watch tell you when a relay is worth it: a limit was hit, a large session has gone cold, or the conversation was compacted.

Questions

Does Relayvora send my code anywhere?+

No. Checkpoints stay on your machine and there is no telemetry. Only if you run and confirm sync or send do handoffs go to your own Git remote.

Do I need a paid plan for both agents?+

You need access to the agent you are switching to. Relayvora itself is free and open source (MIT).

Does it work with the VS Code extensions?+

Yes. The Claude Code and Codex extensions write sessions to the same place as the CLIs, and Relayvora finds the CLI bundled with the extension in VS Code, Cursor, Windsurf and VSCodium.
