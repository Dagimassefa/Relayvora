Relayvora/MCP server

GUIDE / MCP

The Relayvora MCP server: handoffs for any agent.

relayvora mcp serves the Model Context Protocol on stdio. Add it once, and the agent can fetch a handoff or save a checkpoint itself, including agents Relayvora has no adapter for.

npm install -g relayvoraFree · open source · local-first

Add it to your agent

Claude Code and Codex:

claude mcp add relayvora -- relayvora mcp
codex mcp add relayvora -- relayvora mcp

Cursor (.cursor/mcp.json), Windsurf (~/.codeium/windsurf/mcp_config.json) and others:

{ "mcpServers": { "relayvora": { "command": "relayvora", "args": ["mcp"] } } }

VS Code and GitHub Copilot (.vscode/mcp.json):

{ "servers": { "relayvora": { "command": "relayvora", "args": ["mcp"] } } }

Without a global install, use "command": "npx", "args": ["-y", "relayvora", "mcp"].

Tools the agent gets

ToolWhat it does
get_handoffReads a handoff saved for this project (default: the latest). Read-only.
create_checkpointSaves the agent’s goal, completed and pending steps, blockers and decisions, plus Git evidence from the repository.
list_checkpointsLists this project’s checkpoints.
inboxChecks what teammates sent and imports it.
import_checkpointImports an export file or a shared checkpoint, optionally applying its uncommitted changes.

Then ask the agent to “continue from the Relayvora handoff” or to “save a Relayvora checkpoint”.

Designed to stay in your hands

The server never pushes to a remote and never runs commands: sharing (sync, send) and test runs stay with you at the terminal. Tools that write files are marked as such, so clients can ask before using them, and a handoff that came from someone else is marked as imported and unverified.

Because it runs no commands, a checkpoint saved through MCP records Git evidence but not test results. For a verified test run, use relayvora handoff --to codex --verify auto in the terminal.

Listed in the HOL Guard catalog

Relayvora is an external, opt-in MCP server in HOL Guard’s catalog, reviewed by its maintainers. Guard recognises the server when it is launched as relayvora mcp and stays off until you enable it. Once enabled, it applies these defaults:

ToolGuard default
list_checkpoints, get_handoffGuard’s normal handling. Both only read checkpoints saved in the project.
create_checkpointAsks first. It reads agent session records, writes under .relayvora/, and removes checkpoints past retention (30 days by default).
inbox, import_checkpointAsks first. They fetch from a Git remote, or can apply carried changes to your working tree.

Guard matches the installed relayvora command, so use the global install rather than npx if you want these defaults to apply.

Questions

Which clients does it work with?+

Any client that supports MCP servers over stdio, including Claude Code, Codex, Cursor, Windsurf and VS Code with GitHub Copilot.

Can an agent push code or run commands through it?+

No. The server never pushes to a remote and never runs commands.

Which project does it use?+

The folder the editor or agent started the server in. Each tool also accepts a project path inside that folder.
